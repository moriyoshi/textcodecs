# Project journal

Read [.agents/docs/JOURNAL.md](.agents/docs/JOURNAL.md) for project history,
decisions, mapping caveats, and release considerations relevant to your work.

When work produces a durable finding, decision, caveat, or lesson, update the
journal:

- Add a detailed entry to **Chronological project history** in the order the
  work happened. Use a numbered `###` heading and explain the request,
  investigation, outcome, and relevant paths or tests.
- Record dates, measurements, and outcomes only when known. Mark uncertainty
  explicitly, including when an event's place in the chronology is unknown.
- Preserve earlier entries; correct them when evidence shows they are wrong,
  and update the topical reference sections when their guidance changes.
- Update the journal's `Last updated` date when making changes.

Keep routine status and transient command output out of the journal. The
user-facing README and source-specific documentation remain the authoritative
places for usage instructions and current mapping details.
